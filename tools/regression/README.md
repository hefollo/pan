# 三项高风险修复的离线回归

运行 `php -n tools/regression/fatal_bugs.php`。仅在 CLI 执行，加载实际生产函数，使用内存数据库/存储桩和临时文件，不启动网站、不连接数据库或云端。覆盖数据库失败不删除、命名锁失败、秒传旧引用、事务回滚及幂等重试、直传快照校验和凭证重放，另调用实际 S3/OSS/COS 签名实现检查暂存 key 和大小限制。

这些测试不替代真实 MySQL 并发、云端 SDK 和桶策略的集成验证。服务器需支持 MySQL 5.7.5+ 或支持多命名锁的 MariaDB；命名锁不可用时变更会返回忙/失败，不会无锁继续。订单表和用户表必须使用 InnoDB（安装脚本默认如此）。

删除回归还覆盖 SQL 失败/零行、共享引用、旧 storage 空值、计数失败/异常、存储清理失败/异常、等待锁期间记录变化和命名锁失败。四个删除入口统一调用 `delete_file_record`：对已鉴权快照在锁内复查，使用 `query()->rowCount()` 确认删除一行，然后统计所有剩余引用。这里不能使用参数化 `PdoHelper::exec()` 判断受影响行数，因为它只返回执行是否成功。

后台批量入口补充测试：分别运行 `php -n tools/regression/delete_admin.php mixed`、`php -n tools/regression/delete_admin.php all-failed`、`php -n tools/regression/delete_admin.php all-success`。该脚本仅提取并执行实际后台批量操作分支，注入内存 DB/存储桩，验证混合/全部失败/全部成功的计数与状态码，不加载网站初始化或外部依赖。

删除函数用于当前自动提交入口。数据库记录删除成功后，清理失败或请求中断可能留下孤儿对象，但不会恢复一条指向丢失内容的记录；接口成功表示记录已删除。后台批量删除分别统计成功和失败。没有新增自动清理队列/定时任务：维护时可在相同命名锁保护下重新调用 `delete_file_blob_if_orphaned($hash, null, $storage)`，每次必须重新检查引用，禁止直接按旧清单删对象。本轮没有执行真实存储清理，也不能从现有回归推断进程崩溃或真实并发已测试。

## 部署注意

- 更新所有修改的 PHP 文件和新增的 `includes/lib/VerifiedUpload.php`，刷新 OPcache。旧的进行中直传需重新开始。
- 新凭证仅写 `<存储前缀>/pending/<随机值>`。发布时下载到服务端临时磁盘，核对真实长度和 MD5，再把该快照写入最终 key；需预留上传文件大小的临时磁盘和相应读回/写入流量。
- 为 `file/pending/`（S3 使用自定义前缀下的 `pending/`）配置过期清理，例如一天。正常请求会尽力删除暂存对象，但中途退出或旧凭证重放可能遗留暂存对象。
- **更新代码不能撤销此前已经签发的最终 key 写凭证**。若要立即关闭旧凭证窗口，需要在云端轮换/撤销原签名凭据并同步站点配置；本次没有替用户执行该外部操作。否则至少等待旧凭证全部失效。旧 OSS/COS 代码把北京时间标成 UTC，OSS 策略可能最长约九小时有效；不要统一按一小时估算。具体以原凭证和云端策略为准。
- 已经受影响的 status=1 但未发权订单不会自动重发，避免正常订单重复发放；请根据收款与用户权益记录在后台定向补发。既有误删文件需从备份/云端版本恢复。

请求级命名锁序列化相同内容的存储写入、建引用和删除；相同内容的耗时上传/审核可能让其他请求等待，超过 10 秒返回忙并可重试。暂存流程修复的是凭证改写，不改变既有 MD5 内容寻址模型。
